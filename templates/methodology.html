DETECTION FRAMEWORK

Detection Methodology

Understand how PhishGuard evaluates suspicious URLs and email content using transparent, rule-based analysis.

01 / Analysis Pipeline

From input validation to risk assessment.

  1. Input validation: Check that submitted data is present and within the permitted length.
  2. Rule evaluation: Inspect the input for predefined suspicious indicators.
  3. Risk scoring: Add the points assigned to triggered rules and cap the total at 100.
  4. Severity classification: Map the final score to a severity level.
  5. Result explanation: Return the score, severity, and triggered indicators.

02 / URL Detection Rules

Structural signals that may indicate a suspicious URL.

Indicator Points Reason
Plain HTTP +15 The URL does not use HTTPS encryption.
IP address hostname +25 An IP address is used instead of a conventional domain name.
@ in URL authority +20 May create confusion about which host the URL actually targets.
Long hostname +10 The hostname exceeds 50 characters.
Many hostname labels +15 The hostname contains more than four dot-separated labels.
Non-ASCII hostname +20 Internationalized characters can sometimes be used deceptively.
Punycode hostname +10 A hostname label starts with the punycode prefix xn--.

03 / Email Detection Rules

Language and content patterns associated with phishing attempts.

Indicator Points Examples
Urgency language +20 Urgent action required; account will be suspended.
Credential request +30 Enter your password; verify your credentials.
Financial request +25 Wire transfer; send gift cards; payment details.
URL in email +10 The email contains an HTTP or HTTPS URL.

04 / Severity Classification

Risk levels assigned using the final score.

Score Severity Interpretation
0–29 Low Few or no indicators were detected.
30–59 Medium Some suspicious indicators were detected.
60–79 High Multiple or higher-weight indicators raised concern.
80–100 Critical The accumulated score indicates a high level of concern.

05 / Limitations and Safe Use

  • Scores are heuristic indicators, not probabilities that a URL or email is malicious.
  • Legitimate content can trigger rules, and sophisticated phishing attempts can evade them.
  • A low score does not prove that a URL or email is safe.
  • PhishGuard analyzes submitted content locally and does not open or fetch submitted URLs.
  • Do not submit real passwords, confidential messages, or sensitive personal information.
